Most of today went into hosted websites and into the admin app our own team works in. The website work is the part a partner sees.

## For our partners

1. The website page no longer has a Code tab. A site's menu, header buttons, pop-up forms and sections are all set through its content and settings.
2. Keel is in the theme picker: every section the template has, rendered in plain white with system type, with no look of its own.
3. An agent changing a phone number or the text in one card now changes that part of the page and leaves the rest alone.

### 1. One path to a website

Until now a site that needed something unusual got it through code, which meant the site drifted away from the template and stopped getting what the template gained. Everything that used to need code is in the content path now.

When something a partner asks for is genuinely out of reach, the agent working on the site says so: what was wanted, what it tried. That goes straight to our team as an improvement against the template, so the gap closes for every site rather than one.

### 2. Keel

Keel is the starting point for a site being designed from scratch, or brought over from one that already exists. Before it, that work began on an opinionated theme and spent its first hours undoing the opinions. Keel has none: brand settings and a site's own CSS do all the shaping.

## Behind the scenes

1. The admin app our team works in has one address for each thing: the queue, the records and the notifications now sit where the work happens instead of on pages of their own.
2. Claim recipes for small business directories learned several more sign-up routes, one run at a time.
3. Work that is stuck on something only a partner can give is now a single conversation naming the need, carrying every task it holds.
4. Help articles are now checked against the change that touched them, and an article edited under a recorded video files its own re-record.

### 2. Teaching an agent to claim a listing

A directory sign-up looks like a form and is not. One network hides its plan behind a consent dialog, one refuses a business name with a colon in it, one sends a code to an inbox before it will show anything, one asks for a phone verification we will not do on a business owner's behalf.

So a run goes as far as it honestly can, stops with screenshots where it cannot, and a person finishes that one by hand and writes down what the site actually did. That becomes the next version of the recipe, and the next run starts further in. Several profiles are sitting in directory review queues tonight that no one had to fill out twice.
